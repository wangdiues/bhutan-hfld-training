## Part 1: Create a Landsat image collection

An image collection is a set of images of the same kind. For example, every Landsat 8 image in Earth Engine is in one collection. You can work with the whole collection, or use filters to make smaller ones for a study area or a time period. Data: [Landsat 8 Collection 2 Tier 1 and real-time TOA](https://developers.google.com/earth-engine/datasets/catalog/LANDSAT_LC08_C02_T1_RT_TOA).

## Part 5: Functions

As scripts grow, functions keep them organised. A function wraps a piece of code (one statement or hundreds of lines) and gives it a name, so you can reuse it. For example, one function might get the data, another analyse it, and a third export it. A function is useful whenever you repeat the same steps, such as computing NDVI for many images.

<CodeBlock script="day-1/custom-functions.js" lines={[50, 54]} />

- `function` is written in lower case, before the name.
- The **name** follows the same rules as variable names: it can't start with a number, and it should say what the function does.
- The **input parameters** go in brackets after the name, separated by commas. Leave the brackets empty if there are none.
- The **code** goes between curly braces.
- A function only runs when you **call** it: its name, the inputs in brackets, and a semicolon.

### Local and global variables

Try printing `Sum` after the function runs: the Console says **Sum is not defined in this scope**. Next, remove the `return Sum;` line and try `var Sum_test = calculate_Sum(75, 82); print(Sum_test);`. There is no error message, but the value is lost: without `return`, a function gives back nothing (`undefined`). A variable created with `var` inside a function is **local**: it exists only inside the function. To get the result out, the function uses `return`, and you store the call in a **global** variable, `Sum_test`. The Console shows 157 twice: once from the `print` inside the function, and once from `Sum_test`.

## Part 6: A cloud-masking function

Turn cloud masking into a function that takes an image and returns it with clouds masked. `ee.Algorithms.Landsat.simpleCloudScore()` gives each pixel a cloud likelihood from 0 to 100. Pixels above the threshold, 40, are masked. Then test the function on one scene over western Bhutan:

<Tabs>
  <TabItem label="JavaScript (Code Editor)">
    <CodeBlock script="day-1/custom-functions.js" lines={[68, 86]} />
  </TabItem>
  <TabItem label="Python (geemap)">
```python
import ee
import geemap

ee.Initialize(project="<your-project>")  # your Earth Engine Cloud project ID

cloud_thresh = 40


def cloudfunction(image):
    cloud_score = ee.Algorithms.Landsat.simpleCloudScore(image)
    cloud01 = cloud_score.select("cloud").gt(cloud_thresh)
    cloudmask = image.mask().And(cloud01.Not())
    return image.mask(cloudmask)


lc8_image = ee.Image("LANDSAT/LC08/C02/T1_RT_TOA/LC08_138041_20260101")
lc8_image_no_clouds = cloudfunction(lc8_image)

m = geemap.Map()
m.centerObject(lc8_image, 8)
m.addLayer(lc8_image_no_clouds, {"bands": ["B6", "B5", "B4"], "min": 0.1, "max": 0.5}, "Landsat8scene_cloudmasked")
m
```
In Python, `and`, `or` and `not` are reserved words, so the Earth Engine methods are spelled `And()`, `Or()` and `Not()`.
  </TabItem>
</Tabs>

Why this matters: a function with one input (an image) and one output (an image) is exactly what `map()` needs. Every cloud mask, index and correction on Day 2 is written this way.

study_area = (
    ee.FeatureCollection("USDOS/LSIB_SIMPLE/2017").filter(ee.Filter.eq("country_na", "Bhutan")).geometry()

<Theory title="Client and server">
Your script runs in two places. Plain JavaScript (variables, `function`, `if`, loops) runs in your **browser**, the client. Earth Engine objects (`ee.Image`, `ee.Number`, `ee.ImageCollection`) are instructions sent to Google's **servers**, which do the work only when you `print()`, add a layer or export. That is why `calculate_Sum` uses `ee.Number(…).add()`, why you use `map()` instead of a JavaScript `for` loop over a collection, and why you can't use an `ee.Number` in a JavaScript `if`.
</Theory>

### Client errors and server errors

| | Client-side error | Server-side error |
|---|---|---|
| Where it happens | In your browser, before anything is sent to Earth Engine | On Google's servers, while Earth Engine computes |
| Typical message | `Sum is not defined in this scope`; `… is not a function` | `Image.select: Pattern 'B8' did not match any bands`; `User memory limit exceeded` |
| Typical cause | A typo, a local variable used outside its function, a missing `return` | A band or property that doesn't exist, too much data at once |
| Fix | Read the line number and check names and scope | Print the object (`bandNames()`, `first()`), filter more, or use a larger scale |

## Key functions

| Function | What it does |
|---|---|
| `function name(params) { …; return x; }` | Defines a reusable function |
| `collection.map(fn)` | Applies a function to every image; returns a collection |
| `collection.size()`, `collection.toList(n).length()` | Count the images |
| `collection.aggregate_stats(property)` | Statistics of a property across images |
| `collection.sort(property, ascending).limit(n)` | The first n images in a given order |
| `ee.Algorithms.Landsat.simpleCloudScore(image)` | Adds a 0–100 cloud likelihood band to a Landsat TOA image |
| `image.mask()`, `image.updateMask()` | Read or set which pixels are valid |

## Common mistakes

- **No `return`.** A mapped function without `return` fails with the error "User-defined methods must return a value".
- **Returning the wrong type.** A function for `map()` over an image collection must return an image. Returning a number or a string fails.
- **Using `print()` or `Map.addLayer()` inside a mapped function.** They run on the client, which `map()` can't do. Remove them.
- **Using the wrong dataset with `simpleCloudScore`.** It expects Landsat TOA reflectance; with surface reflectance the scores are wrong.
- **An end date that is excluded.** `filterDate('2025-01-01', '2025-12-31')` leaves out 31 December. Use `'2026-01-01'` to include the whole year.
