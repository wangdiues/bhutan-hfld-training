## What is a Random Forest?

<Term id="random-forest" /> is an **ensemble classifier**: it builds many decision trees and outputs the class that most trees vote for (the mode of their outputs) <Cite id="breiman2001" />. The idea of random decision forests was first proposed by Tin Kam Ho at Bell Labs in 1995; Breiman's version combines his "bagging" idea with random selection of features.

A Random Forest has four ingredients:

1. **decision trees**;
2. **bagging** (bootstrap aggregating);
3. **random feature selection**;
4. **ensemble modelling**: combining the trees' votes.

## Decision trees

A **decision tree** is a tree-shaped set of questions. Each branch is a possible answer; following the answers from the top leads to a decision. Upside down, it looks like a tree, which is where the name comes from.

| Term | Meaning |
|---|---|
| **Root node** | the first question, which splits all the training data |
| **Decision node** | a question further down that splits a subset again |
| **Leaf node** | the end of a branch, which gives the class (or value) |
| **Entropy** | how mixed the classes are in a set of samples |
| **Information gain** | how much a split reduces entropy |

### Entropy and information gain

**Entropy** measures disorder. A set where every sample is the same class has entropy 0; a set evenly split between classes has the highest entropy.

<Theory title="Entropy and information gain">
For a set with class proportions $p_i$, $E = -\sum_i p_i \log_2 p_i$. A split divides the set into subsets; its **information gain** is the entropy before minus the size-weighted entropy after: $IG = E_1 - E_2$, with $E_2 = \sum_k \frac{n_k}{n} E_k$. The tree picks the split with the largest gain.
</Theory>

### A worked example: 10 training pixels

Suppose you have 10 labelled pixels from a Sentinel-2 composite of western Bhutan: 5 forest, 3 grassland and 2 water.

**Entropy before any split:**

$E_1 = -(0.5\log_2 0.5 + 0.3\log_2 0.3 + 0.2\log_2 0.2) = 0.500 + 0.521 + 0.464 = 1.485$

Two candidate questions:

| Split | Yes branch | No branch | Weighted entropy $E_2$ | Information gain |
|---|---|---|---|---|
| NDVI > 0.5? | 6 pixels: 5 forest, 1 grass (E = 0.650) | 4 pixels: 2 grass, 2 water (E = 1.000) | 0.6 × 0.650 + 0.4 × 1.000 = 0.790 | 1.485 − 0.790 = **0.695** |
| NIR reflectance < 0.10? | 2 pixels: 2 water (E = 0) | 8 pixels: 5 forest, 3 grass (E = 0.954) | 0.2 × 0 + 0.8 × 0.954 = 0.763 | 1.485 − 0.763 = **0.722** |

The NIR question gains more information, so it becomes the **root node**: it separates the water perfectly. The tree then asks NDVI > 0.5 on the remaining 8 pixels to separate forest from grassland, and so on until the leaves are pure or too small to split.

Build your own tree, and watch entropy change with each split, in the [decision tree playground](/bhutan-hfld-training/labs/decision-tree-playground/).

<Callout type="why">
Why this matters: Earth Engine's Random Forest does exactly this for every tree, over all your covariates (bands, indices, elevation, slope), choosing at each node the question that best separates your training classes.
</Callout>

### Regression trees

The same algorithm predicts numbers instead of classes, for example tree canopy cover. It uses **mean squared error** instead of information gain to choose splits, and each leaf gives a value instead of a class. A classic remote-sensing example predicts percentage tree crown cover from Landsat reflectance, elevation, aspect and slope.

## From one tree to a forest

A single deep tree fits its training data almost perfectly, noise included (it **overfits**), and a small change in the data can change the whole tree. Random Forest fixes this with two kinds of randomness:

1. **Bagging.** Each tree is trained on a **bootstrap sample**: as many samples as the training set, drawn at random **with replacement**. Each tree sees a slightly different dataset; on average about a third of the samples are left out of each tree. These are the **out-of-bag** samples, used to estimate accuracy without a separate test set.
2. **Random feature selection.** At each node, a tree may only choose from a random subset of the variables (often about the square root of their number). This stops every tree from relying on the same strongest variable, so the trees are less alike.

Each tree then votes, and the **majority vote** is the forest's prediction. For regression, the forest averages the trees' predictions. Because the trees' errors are partly independent, they cancel out.

The forest can also report the share of trees voting for each class. That share is a **probability**, and Day 3 uses it to make [forest primitives](/bhutan-hfld-training/day-3/forest-primitives/): a 0–100 probability layer for each class.

## Strengths and weaknesses

**Advantages**

- One of the most accurate general-purpose learning algorithms for many datasets.
- Runs efficiently on large datasets.
- Handles thousands of input variables without removing any first.
- Estimates which variables matter for the classification (variable importance).
- Gives an internal, unbiased estimate of the generalisation error as the forest grows (out-of-bag error).
- Copes well with missing data and keeps its accuracy when a large share of data is missing (in Breiman's original method; in Earth Engine, masked input pixels give masked output, so fill gaps in the covariates first).

**Disadvantages**

- It can overfit datasets with noisy classification or regression tasks.
- For categorical variables with different numbers of levels, it favours variables with more levels, so its variable importance is unreliable for that kind of data.
- It is poor at predicting **out-of-distribution** samples: conditions not represented in the training data, such as a land-cover type, elevation range or year it never saw.

**When few variables matter.** If there are many variables but only a few are relevant, a small random subset per split may rarely include a relevant one. With 3 relevant and 100 irrelevant variables, and about 10 variables tried per split, the chance that a given split sees at least one relevant variable is only about 0.25. Choose covariates thoughtfully rather than adding everything.

<Callout type="bhutan">
Bhutan context: Bhutan's forests range from subtropical broadleaf in the south to fir and juniper near the treeline, over steep slopes. Random Forest handles this mix of spectral, seasonal and terrain covariates well, but only for conditions the training data covers: collect training points across elevation zones, aspects and Dzongkhags, not just near roads.
</Callout>

## Common mistakes

- **Using the same samples for training and accuracy assessment.** Out-of-bag error helps, but reporting accuracy needs an independent sample (Day 5).
- **Training only where it is easy to collect points,** so the forest meets "out-of-distribution" pixels elsewhere.
- **Too few trees.** Results vary from run to run; 100–500 trees is common.
- **Reading variable importance as cause.** It shows what the model used, not what drives land cover.

After the NIR split, the tree asks **NDVI > 0.5?** of the 8 non-water pixels (5 forest, 3 grassland). The yes branch gets 5 forest and 1 grassland; the no branch gets 2 grassland. What is the information gain of this split? Would a split that sent all 5 forest one way and all 3 grassland the other do better?

<Fragment slot="solution">
Before: $E_1 = 0.954$. Yes branch (5 forest, 1 grass): $E = 0.650$, weight $6/8$. No branch (2 grass): $E = 0$, weight $2/8$. So $E_2 = 0.75 	imes 0.650 = 0.488$ and the gain is $0.954 - 0.488 = 0.467$. A perfect split (5 / 3) would leave both branches pure, $E_2 = 0$, for the largest possible gain, 0.954. The tree would split the yes branch again (for example on NIR or SWIR) to separate the remaining grassland pixel.
