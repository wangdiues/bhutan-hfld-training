Land-cover monitoring is often about **change**: how much forest was lost (or gained) over a period. A change map comes from comparing forest at the start and at the end of the period. That map is not the final answer. It is used to divide the country into <Term id="stratum">strata</Term> for the reference sample on Day 5, where accuracy and area are estimated <Cite id="olofsson2014" />.

## From two forest maps to four strata

For each pixel, combine its forest status at the start and at the end of the period:

| Start | End | Stratum | Code |
|---|---|---|---|
| forest | forest | **stable forest** | 1 |
| forest | not forest | **loss** | 2 |
| not forest | not forest | **stable non-forest** | 3 |
| not forest | forest | **gain** | 4 |

A small function does this for any two forest masks (1 = forest, 0 = not), so it works with any source:

<CodeBlock script="day-3/change-strata.js" lines={[11, 33]} />

`ee.Image(0).where(condition, value)` starts from 0 and writes each stratum code where its condition is true. The result keeps only pixels mapped in both years.

## Part A: strata from Hansen Global Forest Change

To run straight away without training assets, use the open [Hansen Global Forest Change](https://developers.google.com/earth-engine/datasets/catalog/UMD_hansen_global_forest_change_2023_v1_11) data: tree canopy cover in 2000 and the year of loss (2001–2023). Forest at the start of 2020 is forest in 2000 with no loss up to 2019; forest at the end of 2023 has no loss up to 2023. Then compute the mapped area of each stratum with `ee.Image.pixelArea()` and a grouped sum:

```python
import ee
import geemap

ee.Initialize(project="<your-project>")  # your Earth Engine Cloud project ID

bhutan = ee.FeatureCollection("FAO/GAUL/2015/level0").filter(ee.Filter.eq("ADM0_NAME", "Bhutan"))

def make_strata(forest_start, forest_end):
    return (
        ee.Image(0)
        .where(forest_start.eq(1).And(forest_end.eq(1)), 1)  # stable forest
        .where(forest_start.eq(1).And(forest_end.eq(0)), 2)  # loss
        .where(forest_start.eq(0).And(forest_end.eq(0)), 3)  # stable non-forest
        .where(forest_start.eq(0).And(forest_end.eq(1)), 4)  # gain
        .updateMask(forest_start.mask().And(forest_end.mask()))
        .rename("stratum")
        .toByte()
    )

gfc = ee.Image("UMD/hansen/global_forest_change_2023_v1_11").clip(bhutan)
forest2000 = gfc.select("treecover2000").gte(10)
lossyear = gfc.select("lossyear")
strata = make_strata(
    forest2000.And(lossyear.gte(1).And(lossyear.lte(19)).Not()),
    forest2000.And(lossyear.gte(1).And(lossyear.lte(23)).Not()),
)
areas = ee.Image.pixelArea().divide(10000).addBands(strata).reduceRegion(
    reducer=ee.Reducer.sum().group(groupField=1, groupName="stratum"),
    geometry=bhutan.geometry(), scale=30, maxPixels=1e13,
)
print(areas.getInfo())

m = geemap.Map()
m.centerObject(bhutan, 8)
m.addLayer(strata, {"min": 1, "max": 4, "palette": ["1a9850", "d73027", "bdbdbd", "4575b4"]}, "Strata 2020-2023")
m
```
  </TabItem>
</Tabs>

The map uses green for stable forest, red for loss and grey for stable non-forest; the Inspector shows the stratum code of any pixel, and the Console lists the area of each. Part A has no gain stratum: forest at the end can only be forest at the start minus losses, so code 4 never occurs. Part B, with two independent maps, can show gain (in blue).

<Callout type="mistake" title="Hansen is not Bhutan's forest map">
Hansen's "tree cover" is not a forest definition: it includes plantations and orchards, its loss year can lag the real event, and gain is only mapped for 2000–2012. It is useful for practice and for comparison, but Bhutan's activity data should come from its own maps, made with its forest definition (Part B). The 10% canopy threshold here is only an example; set it from the forest definition you report.
</Callout>

<Callout type="why">
Why this matters: comparing two independently classified maps adds the errors of both. A pixel misclassified in either year looks like change. That is why the loss stratum always contains false change, and why its area must be estimated from a reference sample rather than counted from the map.
</Callout>

## Why loss needs its own stratum

In Bhutan, forest loss covers a small share of the country over a few years (compare the area of stratum 2 with the total in the Console). If you drew a simple random sample of, say, 1,000 points across the country, only a handful would fall in places where loss really happened, too few to estimate the loss area or its accuracy with any confidence.

**Stratified sampling** fixes this. Because loss is its own stratum, you can put many more samples there than its area alone would give, for example 100 or more, while the large stable strata get fewer than their share. Each stratum's samples are later weighted by its mapped area, so the estimate stays unbiased <Cite id="olofsson2014" />.

<Theory title="Weights and allocation" more="/explanation/area-estimation/">
A stratum's weight is its share of the mapped area, $W_h = A_h / A$. With stratified estimation, any allocation of samples to strata gives unbiased area estimates, as long as each stratum's samples are weighted by $W_h$. So you can over-sample the rare loss stratum to make its estimate precise. [Lab: sample size](/lulc-mapping-training/labs/sample-size-calculator/) computes how many samples you need and compares allocations.
</Theory>

<Callout type="bhutan">
Bhutan context: the Day 5 sampling design uses forest strata plus a deforestation stratum, exactly this idea. Gain is rare and often unreliable in maps; many programmes merge it with stable non-forest or keep it as a small separate stratum, depending on whether removals are reported.
</Callout>

## Key functions

| Function | What it does |
|---|---|
| `ee.Image(0).where(condition, value)` | Writes a value where a condition is true |
| `a.and(b)`, `a.not()` | Combine masks |
| `image.updateMask(mask)` | Keeps only pixels mapped in both years |
| `ee.Image.pixelArea()` | Area of each pixel in m² |
| `ee.Reducer.sum().group({groupField, groupName})` | Sums a band separately for each value of another band |

## Common mistakes

- **Reporting map change as the answer.** Map-based loss area is biased by classification errors; estimate area from the reference sample (Day 5).
- **Different forest definitions in the two years** (different thresholds, classes or sensors): differences in method then look like change.
- **Forgetting that `lossyear` counts from 2001**: 19 means 2019, 23 means 2023.
- **Strata with different masks in each year.** Unmatched masks shrink the area; use the same area of interest and sensor for both years.
