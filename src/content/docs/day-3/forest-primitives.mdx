A <Term id="primitive" /> is a probability layer for one land-cover class: for every pixel, the likelihood (0 to 1, or 0 to 100) that it belongs to that class. Instead of one classifier choosing among all classes at once, you train a separate **one-class-versus-the-rest** Random Forest for each class, then combine the primitives with rules on Day 4 (the [assemblage](/bhutan-hfld-training/day-4/assemblage/)) <Cite id="saah2020" />. This lesson builds the **forest** primitive; the same script makes the others by changing one word.

<Callout type="mistake" title="Inputs you need">
The script reads two assets from the training project: the labelled samples `trainingData/Bhutan_labels_multiclass` and a 2025 Landsat composite (one participant's export, `landsatComposite/bhutan_ls89_2025_TashiY`). Without access, use your own composite from the [Landsat MRV composite](/bhutan-hfld-training/day-2/landsat-mrv-composite/) lesson and your own labelled points with a `class_name` property ([Collecting training data](/bhutan-hfld-training/day-4/training-data/)). Change the export `assetId` to your own project.
</Callout>

## Part 8: Balance the training set

Non-forest samples (all the other classes together) usually outnumber forest samples. A classifier trained on unbalanced data leans towards the larger group. So the training set keeps all target samples and a random selection of the same number of non-target samples. The validation set stays unbalanced, so its accuracy reflects the real mix.

<CodeBlock script="day-3/forest-primitives.js" lines={[274, 292]} />

```python
# Assumes `training` (a FeatureCollection with the covariate bands and "target") and
# `bands` (the covariate band names) built as in the JavaScript version.
classifier = ee.Classifier.smileRandomForest(numberOfTrees=200, bagFraction=0.7, seed=42).train(
    features=training, classProperty="target", inputProperties=bands
)
validation_matrix = validation.classify(classifier).errorMatrix("target", "classification")
print("Validation overall accuracy:", validation_matrix.accuracy().getInfo())
print("Variable importance:", classifier.explain().get("importance").getInfo())

target_probability = covariates.select(bands).classify(classifier.setOutputMode("PROBABILITY"))
```
  </TabItem>
</Tabs>

- `numberOfTrees: 200`: the number of decision trees.
- `bagFraction: 0.7`: each tree is trained on a random 70% of the training samples.
- `seed: 42`: makes the random choices repeatable, so you get the same forest each run.

## Part 10: Accuracy

The script builds a confusion matrix twice: on the **training** samples (how well the forest fits the data it learned from; this is always optimistic) and on the **validation** samples (how well it predicts samples it did not see).

<CodeBlock script="day-3/forest-primitives.js" lines={[312, 335]} />

| Measure | Meaning |
|---|---|
| Overall accuracy | share of samples classified correctly |
| Kappa | agreement beyond what chance would give |
| Producer's accuracy | for each class, the share of its reference samples the model got right (omission errors) |
| Consumer's accuracy | Earth Engine's name for user's accuracy: for each predicted class, the share that is correct (commission errors) |

<Callout type="mistake" title="This is not the accuracy you report">
The 10% validation samples come from the same training set, often collected in the same places. They show how well the model generalises, but they are not a statistically valid accuracy assessment. For ART-TREES reporting, accuracy and areas come from an independent stratified sample interpreted in Collect Earth Online (Day 5).
</Callout>

## Part 11: Variable importance

`classifier.explain()` reports how much each covariate contributed to the forest's splits. Use it to see which inputs separate the target class, and to drop covariates that add nothing. It also contains `outOfBagErrorEstimate`: with `bagFraction: 0.7`, each tree leaves 30% of the training samples out, and the forest's error on those out-of-bag samples is a quick, built-in estimate of its accuracy (print `explanation.get('outOfBagErrorEstimate')`).

<CodeBlock script="day-3/forest-primitives.js" lines={[336, 339]} />

## Part 12: Classify and map the probability

The classifier applied to the covariate stack gives a binary map (1 = forest, 0 = non-forest). In **probability mode** it gives, for each pixel, the share of trees that voted forest: the forest primitive.

<CodeBlock script="day-3/forest-primitives.js" lines={[340, 386]} />

<Theory title="Why probabilities, not classes" more="/explanation/rlcms-primitives-and-assemblage/">
A binary map hides how sure the model is: a pixel at 0.51 and one at 0.99 both become "forest". A probability layer keeps that information, so the assemblage step can set its own thresholds and decide between classes that compete for the same pixel (for example, forest at 0.55 and cropland at 0.60).
</Theory>

## Part 13: Export

Export the binary map and the probability map to Drive, the validation points as a CSV, and the probability layer to an asset. Primitive assets follow one naming convention: a data-source prefix (`ls_` for Landsat, `s2_` for Sentinel-2, `afe_` for AlphaEarth embeddings), then `<Class>_<year>`, for example `ls_Forest_2025`. Keeping the same pattern for every class and year makes the primitives easy to find and load together in the [assemblage](/bhutan-hfld-training/day-4/assemblage/) (which, in the training, used Sentinel-2 primitives, `s2_<Class>_2025`).

## Key functions

| Function | What it does |
|---|---|
| `ee.Algorithms.If(cond, a, b)` | Server-side if/else, here inside `map()` |
| `image.sampleRegions({collection, properties, scale})` | Reads covariate values at points |
| `collection.randomColumn(name, seed)` | Adds a uniform random number (0–1) to each feature |
| `.sort(column).limit(n)` | Takes n features in random order (balancing) |
| `ee.Classifier.smileRandomForest({...}).train({...})` | Trains a Random Forest |
| `classifier.setOutputMode('PROBABILITY')` | Returns class-1 probabilities instead of labels |
| `features.classify(c).errorMatrix(actual, predicted)` | Confusion matrix and accuracy measures |
| `classifier.explain()` | Variable importance and other model details |

## Common mistakes

- **Reporting training accuracy.** It is always high; use the validation set to judge the model, and Day 5's independent sample to report.
- **A `class_name` that doesn't match `targetClass` exactly** (for example "Cropland" vs "CropLand"): every sample becomes non-target. Check the binary histogram.
- **Masked covariates.** A masked band in the stack masks the pixel in the output; fill water layers with `unmask(0)` as the script does.
- **Exporting with the wrong year in the name.** Keep the year of the composite.

<Callout type="bhutan">
Bhutan context: the forest primitive is the core of Bhutan's activity data. Check it against what you know: forest should follow the valley slopes, with lower probabilities on farmland near Paro and Punakha, on high pastures and above the treeline.
</Callout>
