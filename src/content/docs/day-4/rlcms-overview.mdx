## What is RLCMS?

The <Term id="rlcms" /> (Regional Land Cover Monitoring System) uses satellite data to produce customised, high-quality land-cover maps for a region. It works anywhere in the world because it uses publicly available global data (Landsat, MODIS, Sentinel-2) and an adaptable design: the **assembly logic** that turns probabilities into a map can be changed to match each country's land-cover classes and monitoring goals <Cite id="saah2020" />.

RLCMS was developed by SERVIR-Mekong (now SERVIR-Southeast Asia, SERVIR-SEA) with the support of the U.S. Forest Service, NASA's Applied Sciences Program, Google, the University of Maryland and the governments of countries in the region <Cite id="saah2020" />. The course uses the same approach for Bhutan.

## The four stages

<Steps>

1. **Composite preparation.** Pre-process images (shadow and cloud masking, BRDF and topographic correction) and build composites. Any available imagery can be used: Landsat 5, 7, 8 and 9, Sentinel-1, Sentinel-2, or Planet NICFI. *Course:* [Sentinel-2](/lulc-mapping-training/day-2/sentinel-2-mrv-composite/) and [Landsat](/lulc-mapping-training/day-2/landsat-mrv-composite/) MRV composites.

2. **Training data preparation.** Define the land-cover typology (the list of classes) for the country, and collect reference data for each class. The reference data are split into training data and validation data, and the training data are sampled to get covariate values at each point. *Course:* [Calculating covariates](/lulc-mapping-training/day-3/covariates/) and [Collecting training data](/lulc-mapping-training/day-4/training-data/).

3. **Primitive layer generation.** A classifier, trained on the sampled data, produces a primitive for each class: the probability that a pixel is that class. Each primitive's accuracy is assessed. *Course:* [Forest primitives](/lulc-mapping-training/day-3/forest-primitives/).

4. **Assemblage.** A decision tree with user-set thresholds combines the primitives into the final land-cover map. The thresholds come from visual assessment and from plots of each primitive's accuracy against its probability. *Course:* [Assemblage](/lulc-mapping-training/day-4/assemblage/).

</Steps>

<Callout type="why">
Why this matters: splitting the work into stages means each part can be checked and improved on its own. A better composite, more training data or a changed class definition does not mean starting again.
</Callout>

## A modular system

Three features make RLCMS practical for a national agency:

- **Modular architecture.** Composites, covariates, primitives and the assembly are separate modules. Each can be replaced, for example a new sensor for the composites, without changing the others.
- **Customisable to the agency's classification system.** The assembly algorithm can be reconfigured to produce the classes a country reports, from the same biophysical primitives (for example evergreen and deciduous forest, tree canopy cover, cropland, urban and built-up, water). A country can assemble them into its own classes instead of the regional typology.
- **Easily updated.** New data and better algorithms can be added each year, and validation data from one year improve the next.

## Terms to know

**Machine learning (ML).** A kind of artificial intelligence in which algorithms learn patterns and relationships from large datasets, then use them to make predictions or decisions, improving as they get more data. RLCMS uses Random Forest and convolutional neural networks.

**Classifier.** An ML algorithm that sorts data into categories (classes). It learns from training data and predicts the class of new data.

**<Term id="random-forest" /> classifier.** An ML algorithm that uses many decision trees, each built from a random subset of the training data, and takes the majority vote of the trees as the final class. It predicts most classes well, but can struggle with classes whose data look alike. See [Random Forest theory](/lulc-mapping-training/day-3/random-forest/).

**Training data.** Reference points with known classes, collected in the field or from high-resolution imagery. Reference points are split into **training** and **validation** data. At each training point, the covariate values are read from the image (sampling); the classifier learns from these "known" points and predicts the class of every other ("unknown") pixel.

**<Term id="covariate">Covariates</Term>.** The variables a classifier uses, calculated from the composite bands (indices, Tasseled Cap, terrain and others). In Random Forest, the best split at each node is searched among a random subset of covariates. Fewer covariates means less computation, so RLCMS runs the classifier twice: first with all covariates, to find the most important ones (**feature selection**), then with only those, for an efficient and accurate model.

**<Term id="primitive">Primitives</Term>.** The output of the model: a probability map for each land-cover class, one map per class. Each pixel's value says how likely it is to be that class, based on how similar its covariate values are to what the model learned from the training data for that class. The accuracy of each primitive can be evaluated separately.

**<Term id="assemblage">Assemblage</Term> map.** The land-cover map made by combining the primitives with rules that reflect the user's class definitions and priorities, while keeping the uncertainty information. In the simplest version, each pixel takes the class whose primitive has the highest probability; in practice a decision tree with thresholds and a class order is used.

<Callout type="bhutan">
Bhutan context: the classes Bhutan reports (forest, cropland, grassland, settlement, wetland and other land) are produced by assembling Bhutan's own primitives, with rules that put Bhutan's forest definition into practice.
</Callout>

## Common mistakes

- **Treating a primitive as a map.** A primitive is a probability; the class comes only after assemblage.
- **Using validation points for training.** Keep them separate, or the accuracy is overstated.
- **Adding every possible covariate.** Feature selection keeps the model efficient and often more accurate.
