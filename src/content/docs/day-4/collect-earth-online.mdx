<Term id="ceo" /> ([collect.earth](https://collect.earth)) is a free, web-based tool for interpreting sample plots on high-resolution imagery. Several interpreters can work on the same project, and the results are exported as tables. Here it turns the stratified sample from [Stratified sampling in GEE](/bhutan-hfld-training/day-5/stratified-sampling-gee/) into **reference data**: the "true" class of each sample, which is compared with the map on Day 5.

## The response design

Before anyone interprets a plot, write down the **response design**: the rules that decide what the reference label of a sample is <Cite id="olofsson2014" />. It has four parts:

1. **The assessment unit.** What is labelled: here a 30 m × 30 m plot matching one map pixel (or the sample point at its centre).
2. **The sources of reference data.** Which imagery and dates are used: for example high-resolution imagery in CEO, Sentinel-2 and Landsat time series for the reporting years, and field knowledge.
3. **The labelling protocol.** The class definitions and the rules for hard cases.
4. **The definition of agreement.** How a reference label is compared with the map: here, how the start and end land-cover answers become a reference **stratum class** (forest, non-forest or deforestation) to set against the map's stratum.

For Bhutan's HFLD work, the protocol should include:

| Rule | Example |
|---|---|
| **Use the same class definitions as the map**, including the forest definition | minimum canopy cover, tree height and area as in Bhutan's forest definition |
| **Decide mixed plots by a fixed rule** | the class covering more than half the plot; or forest if canopy cover in the plot meets the forest definition |
| **Define change** with dates | deforestation = forest at the start of the period and not forest at the end, with the loss visible in imagery between those dates |
| **Say what to do when you can't tell** | no imagery for the date, cloud or shadow: mark the sample *uninterpretable* with a reason, never guess |
| **Record confidence** | high / medium / low, so doubtful samples can be reviewed |

<Callout type="why">
Why this matters: the reference labels are treated as truth. If two interpreters would label the same plot differently, the accuracy and area estimates absorb that disagreement. Clear written rules and a second interpreter for a share of the plots keep the reference data consistent and defensible to a verifier.
</Callout>

## Set up a project

<Steps>

1. **Sign in** at [collect.earth](https://collect.earth) and create (or join) an **institution** for your team.

2. **Create a project** in the institution. Give it a clear name, for example *Bhutan HFLD reference sample 2020–2025*, and a description of the period and the map being assessed.

3. **Choose the imagery.** Add the basemaps interpreters will use: high-resolution imagery, plus Sentinel-2 or Landsat imagery for the start and end of the reporting period, so change can be seen.

4. **Upload the plots and samples.** Use the shapefiles exported in [Stratified sampling in GEE](/bhutan-hfld-training/day-5/stratified-sampling-gee/): the plot file (each feature with a `plotID`) and the sample file (each point with a `plotID` and a `sampleID`). Zip each shapefile's parts (.shp, .shx, .dbf, .prj) before uploading. CEO also accepts CSV files with coordinates.

5. **Write the survey questions** from the response design. For example:
   - *Land cover at the end of the period?* Forest, Cropland, Grassland, Settlement, Wetland, Other land.
   - *Land cover at the start of the period?* (the same classes)
   - *Is the plot interpretable?* Yes / No, with a reason.
   - *Confidence?* High / Medium / Low.

   Use exactly the class names of the map, so the results can be compared directly.

6. **Review and publish** the project, and assign interpreters.

</Steps>

<Callout type="mistake" title="Keep the sample unchanged">
Don't move, add or delete plots after the sample is drawn: that breaks the probability design. If a plot can't be interpreted, record that and report how many there were. Leaving them out of the analysis can bias the estimates if they differ from the rest, which is why [Stratified sampling in GEE](/bhutan-hfld-training/day-5/stratified-sampling-gee/) suggests drawing a few spare samples per stratum.
</Callout>

## Interpret the plots

- Look at the **whole plot**, and at its surroundings for context.
- Use the **most recent high-resolution image** for the end of the period, and older imagery or the Sentinel-2/Landsat time series for the start.
- Compare with the **map class only after** labelling, or better, hide it: knowing the map's answer biases interpreters.
- On steep slopes, high-resolution imagery can be shifted by relief; check the plot against the Sentinel-2 view.
- Mark uncertain plots and **review them together** at the end.
- If possible, have a **second interpreter** label 10–20% of the plots, and resolve disagreements by discussion.

## Export the results

When the plots are interpreted, export the **plot** (or sample) data as CSV from the project's data menu. Each row holds the plot and sample IDs, the coordinates, the answers and the interpreter, and usually the attribute fields you uploaded (CEO may add a prefix to their names), so the map stratum `lc_no` may already be in the export.

To analyse them, you need, for each sample, its **map class** (the stratum from Earth Engine) and its **reference class** (from CEO), named the same way:

1. If the export doesn't include `lc_no`, join it with the exported samples on `plotID` (in a spreadsheet, or in Earth Engine after uploading the CSV as an asset).
2. Turn the map stratum codes into names: 1 = Forest, 2 = Non-forest, 3 = Deforestation.
3. Turn each sample's start and end answers into a reference stratum class: forest at both dates = Forest; forest at the start and not at the end = Deforestation; not forest at the end (and not deforestation) = Non-forest.
4. Make a table with two columns, `map` and `reference`, using these names.
3. Paste it into the [accuracy and area calculator](/bhutan-hfld-training/labs/accuracy-area-estimator/), with the mapped area of each stratum.

The trainers' Code Editor script for the CEO demonstration is [code.earthengine.google.com/0cbd5b45585eaf7252becc41c417ae6e](https://code.earthengine.google.com/0cbd5b45585eaf7252becc41c417ae6e).

<Callout type="bhutan">
Bhutan context: high-resolution imagery over Bhutan is often from winter, with long shadows on north-facing slopes, and cloud is common in the monsoon. Plan to use several dates, and keep a record of which image decided each label.
</Callout>

## Common mistakes

- **Labelling from the map** rather than from the imagery.
- **Class names that differ** between the map and the survey (Otherland vs Other land): the comparison then fails.
- **Guessing** on cloudy or shadowed plots instead of marking them uninterpretable.
- **No written rules for mixed plots**, so interpreters decide differently.
