### Train a Gradient Tree Boost model

This time the classifier is **Gradient Tree Boost** rather than Random Forest. Boosting builds trees one after another, each correcting the errors of the previous ones:

<Tabs>
  <TabItem label="JavaScript (Code Editor)">
    <CodeBlock script="day-4/embeddings-classification-similarity.js" lines={[143, 191]} />
  </TabItem>
  <TabItem label="Python (geemap)">
```python
# Assumes `training`, `validation` and `bands` built as in the JavaScript version,
# and `alpha_earth` the 2024 embedding mosaic.
classifier = ee.Classifier.smileGradientTreeBoost(
    numberOfTrees=200, shrinkage=0.05, samplingRate=0.7, loss="LeastSquares", seed=42
).train(features=training, classProperty="target", inputProperties=bands)
matrix = validation.classify(classifier).errorMatrix("target", "classification")
print("Validation overall accuracy:", matrix.accuracy().getInfo())
probability = alpha_earth.select(bands).classify(classifier.setOutputMode("PROBABILITY"))
```
  </TabItem>
</Tabs>

- `numberOfTrees: 200`: trees added one by one.
- `shrinkage: 0.05`: the learning rate; each tree's contribution is scaled down, so learning is slow and steady.
- `samplingRate: 0.7`: each tree sees 70% of the samples (stochastic boosting).
- `loss: "LeastSquares"` only matters for regression; Earth Engine ignores it when the target is a class, as here.

Variable importance is useful as a check, but the embedding axes are learned, so their importance has no physical meaning.

### Cosine similarity and the mean of several samples

For each reference point, turn its 64 values into a constant image and take the dot product with every pixel: that is the cosine similarity. Averaging the similarity maps of several points gives a more robust definition of "like these":

<Tabs>
  <TabItem label="JavaScript (Code Editor)">
    <CodeBlock script="day-4/embeddings-classification-similarity.js" lines={[370, 421]} />
  </TabItem>
  <TabItem label="Python (geemap)">
```python
# Assumes `mosaic` (the 2024 embedding image), `samples` (reference points) and `small_aoi`.
band_names = mosaic.bandNames()
sample_embeddings = mosaic.sampleRegions(collection=samples, scale=10, geometries=True)


def similarity_to(f):
    vec = ee.Image.constant(f.toArray(band_names)).arrayFlatten([band_names]).toFloat()
    return vec.multiply(mosaic).reduce(ee.Reducer.sum()).rename("similarity")


mean_similarity = ee.ImageCollection(sample_embeddings.map(similarity_to)).mean().clip(small_aoi)
similarity_mask = mean_similarity.gt(0.80)
```
  </TabItem>
</Tabs>

Keep pixels with similarity above 0.80, turn them into polygons and their centroids, and export the mask:

## Part C: change between years

The same dot product, between one pixel's embeddings in two years, measures how much it changed. Low values (red) flag change:

<Tabs>
  <TabItem label="JavaScript (Code Editor)">
    <CodeBlock script="day-4/embeddings-classification-similarity.js" lines={[483, 503]} />
  </TabItem>
  <TabItem label="Python (geemap)">
```python
# Assumes `aoi`, the search area geometry.
emb = ee.ImageCollection("GOOGLE/SATELLITE_EMBEDDING/V1/ANNUAL")


def embedding_for(y, aoi):
    return emb.filterDate(f"{y}-01-01", f"{y + 1}-01-01").filterBounds(aoi).mosaic().select("A.*")


change = embedding_for(2023, aoi).multiply(embedding_for(2024, aoi)).reduce(ee.Reducer.sum())
```
  </TabItem>
</Tabs>

Low similarity can also come from a wet year against a dry one, so check flagged places before calling them land-cover change.

## Key functions

| Function | What it does |
|---|---|
| `ee.ImageCollection('GOOGLE/SATELLITE_EMBEDDING/V1/ANNUAL')` | Annual 64-band embeddings |
| `ee.Classifier.smileGradientTreeBoost({...})` | Gradient-boosted trees |
| `feature.toArray(bands)`, `ee.Image.constant(...).arrayFlatten([bands])` | A sample's embedding as a constant 64-band image |
| `a.multiply(b).reduce(ee.Reducer.sum())` | Dot product = cosine similarity |
| `image.reduceToVectors({...})` | Turns a mask into polygons |
| `feature.centroid()` | The centre of each polygon |

## Common mistakes

- **Mixing the embedding year and the label year.** Use labels that describe the embedding's year.
- **Reading low similarity as change without checking.** Seasonal and climatic differences also lower it.
- **One reference point.** Average several to define the target robustly.
- **Interpreting the importance of `A16` or any single axis** as a physical variable.

<Callout type="bhutan">
Bhutan context: built-up areas are small and scattered in Bhutan's valleys, so similarity search with a handful of good examples is a fast way to find candidate settlements, and to check where a settlement primitive may be missing them.
</Callout>
