This lab does by hand what Earth Engine's Random Forest does thousands of times. It starts from the 10 training pixels of the worked example in [What is a Random Forest?](/lulc-mapping-training/day-3/random-forest/#a-worked-example-10-training-pixels): 5 forest, 3 grassland and 2 water. The pixel values are illustrative, not measurements.

<DecisionTreeLab />

## Things to try

1. With the worked example, try the lesson's two questions: **NDVI greater than 0.5** and **NIR reflectance less than 0.10**. Check that the gains are 0.695 and 0.722, as in the lesson. (The lab works with unrounded values, so it shows a weighted entropy of 0.7635 for the NIR split, which the lesson rounds via 0.8 × 0.954 = 0.763.)
2. Now click **Fill in the best split**. The lab tries every threshold halfway between two pixel values and finds a better question than either of the lesson's two. Why does it separate the classes better?
3. Grow the tree until every leaf is pure. How many splits did you need? Would you trust a leaf that holds a single pixel?
4. Switch to **Western Bhutan**, which adds cropland. Split until a leaf holds only forest and cropland: which covariate separates them best? And which one separates cropland from grassland?
5. In Part 2, set the number of trees to 1, then 10, then 100, and change the seed each time. Which result changes more from seed to seed: one tree or a hundred?
6. Classify a pixel at 3,800 m with NDVI 0.55. Is the vote close? Change its NIR value, then the seed: how much does the answer depend on them? What kind of training pixels would make the forest more confident?

<Theory title="Why a forest beats a tree" more="/explanation/random-forest/">
Each tree is grown on a bootstrap sample and sees one random covariate per split, so the trees make different mistakes. When they vote, many of those mistakes cancel out, and the forest's answer changes much less with the sample than a single tree's <Cite id="breiman2001" />. The share of trees voting for a class is roughly what Earth Engine reports as a probability (exactly so when every leaf is pure).
</Theory>

<Callout type="mistake" title="Common mistakes">
- **Growing until every leaf is pure.** The tree then fits noise in the training data. Limit the tree size or the leaf size (`maxNodes` and `minLeafPopulation` in Earth Engine).
- **Judging the model on its training pixels.** The forest is nearly always right on the pixels it learned from. The map's accuracy comes from an independent reference sample (Day 5).
- **Too few, unbalanced training pixels.** With only two water pixels, a single odd pixel changes the tree. Collect samples across Bhutan's regions and elevations.
</Callout>

The lab's maths is in `src/lib/stats/trees.ts`, with automated tests that reproduce the lesson's worked example. Part 2 is a teaching model. Each of its trees gets a bootstrap sample (as many pixels as the training set, drawn with replacement) and one covariate per split. Earth Engine's Random Forest grows larger trees and by default gives each tree half of the samples (`bagFraction` 0.5) and the square root of the number of covariates at each split.
