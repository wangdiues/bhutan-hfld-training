## Feature collections

**Feature collections** are like image collections, but they hold **features** instead of images: a geometry (point, line or polygon) plus attributes. They are the Earth Engine equivalent of vector layers in GIS: each feature is a row, and each attribute is a column.

### Basic vector analysis

The four classic GIS operations all exist in Earth Engine:

| Operation | What it does | Earth Engine |
|---|---|---|
| **Buffer** | a zone of a set width around a point, line or polygon | `geometry.buffer(metres)`, `feature.buffer()` |
| **Clip** | keeps only the part of a dataset inside a boundary, such as land cover within a study area | `image.clip(boundary)`; for vectors `geometry.intersection(boundary)` |
| **Merge** | combines several feature collections into one | `collection.merge(other)` |
| **Union** | dissolves overlapping features into one | `collection.union()`, `geometry.union(other)` |

<CodeBlock script="day-2/feature-basics.js" lines={[23, 53]} />

<Callout type="mistake" title="Vector work is not Earth Engine's strength">
Earth Engine handles these operations, but complex vector editing (snapping, topology, digitising boundaries) is easier in QGIS or ArcGIS. Prepare clean vector data there, then upload it.
</Callout>

## Importing your own data as assets

Uploaded files become **assets**, stored in your Cloud project (or in older "legacy" asset folders) and listed in the **Assets** tab. Click **NEW** to choose the type.

<Image src={newMenu} alt="The Assets tab NEW menu with options for GeoTIFF, shapefile and CSV uploads, image collections and folders." />

### Shapefiles

A shapefile is several files with the same name. You need at least **.shp**, **.shx**, **.dbf** and **.prj**, or a **.zip** of them. The other files (.cpg, .sbn, .sbx, .shp.xml) are optional.

<Image src={shpFiles} alt="The files that make up one shapefile: .cpg, .dbf, .prj, .sbn, .sbx, .shp, .shp.xml and .shx." />

1. **NEW → Shape files (.shp, .shx, .dbf, .prj or .zip)**.
2. Select the files, choose an **Asset ID** (its name and folder), and click **Upload**.
3. Follow the upload in the **Tasks** tab. When it finishes, the asset appears in the Assets tab; click it to import it into your script.

<Image src={shpDialog} alt="The 'Upload a new shapefile asset' dialog with the selected files, asset ID and advanced options." />

### CSV files

A CSV file needs columns for the coordinates, longitude (X) and latitude (Y). The coordinate system defaults to WGS84 (EPSG:4326). Use **Advanced options** to name the X and Y columns or set another CRS.

<Image src={csvMenu} alt="The Assets tab NEW menu with the CSV file option highlighted." />

<Image src={csvDialog} alt="The 'Upload a new CSV asset' dialog with the source file, asset ID and advanced options." />

## Exporting data

Earth Engine computes in the cloud; to keep a result, you **export** it. Exports run as tasks: click **Run** in the **Tasks** tab to start each one.

| Export | `toAsset()` | `toDrive()` | `toCloudStorage()` |
|---|---|---|---|
| `Export.image` | yes | GeoTIFF, TFRecord | GeoTIFF, TFRecord |
| `Export.table` | yes | CSV, GeoJSON, KML, KMZ, SHP, TFRecord | same as Drive |
| `Export.video` | no | MP4 | MP4 |
| `Export.map` (map tiles) | no | no | PNG, JPG |

Tables can also go to `toFeatureView()` (for fast display in apps) and `toBigQuery()`.

### Raster to Google Drive

```js
Export.image.toDrive({
  image: image,
  description: 'image',
  region: region,
  scale: 30,
  crs: 'EPSG:4326',
  maxPixels: 1e13,
  folder: 'GEE'
});
```

- `image`: the image to export;
- `description`: the task's name (and the default file name);
- `region`: the area to export;
- `scale`: the pixel size in metres;
- `crs`: the coordinate system of the output;
- `maxPixels`: the maximum number of pixels allowed; raise it for large areas;
- `folder`: the Google Drive folder, created if it doesn't exist.

### Raster to an asset

```js
Export.image.toAsset({
  image: medianImage,
  description: "Bhutan",
  assetId: "Bhutan",
  region: studyArea.bounds(),
  scale:10,
  maxPixels:1e13
});
```

`assetId` is the asset's name and path in your project. There is no `folder`: use a path such as `projects/<your-project>/assets/composites/bhutan_2025`.

### Vector data to Google Drive

Use `Export.table.toDrive()` to download **vector data** (features) as a file:

```js
Export.table.toDrive({
  collection: features,
  description:'features',
  folder: 'GEE_',
  fileFormat: 'SHP'
});
```

`fileFormat` can be `'CSV'`, `'GeoJSON'`, `'KML'`, `'KMZ'`, `'SHP'` or `'TFRecord'`.

### Vector data to an asset

```js
// Export an ee.FeatureCollection
Export.table.toAsset({
  collection: features,
  description: 'exportToTableAssetExample',
  assetId: 'exampleAssetId',
});
```

### 2. Dynamic World land cover for 2023

[Dynamic World](https://developers.google.com/earth-engine/datasets/catalog/GOOGLE_DYNAMICWORLD_V1) gives a near-real-time 10 m land-cover label for every Sentinel-2 image. Filter it to 2023, display the labels and export them:

```python
import ee
import geemap

ee.Initialize(project="<your-project>")  # your Earth Engine Cloud project ID

aoi = ee.FeatureCollection("FAO/GAUL_SIMPLIFIED_500m/2015/level2").filter(ee.Filter.eq("ADM0_NAME", "Bhutan"))
dw = ee.ImageCollection("GOOGLE/DYNAMICWORLD/V1").filterDate("2023-01-01", "2024-01-01")
classification = dw.mosaic().clip(aoi).select("label")

palette = ["419BDF", "397D49", "88B053", "7A87C6", "E49635", "DFC35A", "C4281B", "A59B8F", "B39FE1"]
m = geemap.Map()
m.centerObject(aoi, 8)
m.addLayer(classification, {"min": 0, "max": 8, "palette": palette}, "Dynamic World Classification")
m

task = ee.batch.Export.image.toDrive(
    image=classification, description="DynamicWorld_2023", region=aoi.geometry(),
    folder="GEE_exports", scale=10, maxPixels=1e13,
)
# task.start()
```
  </TabItem>
</Tabs>

The nine classes, in order 0–8: water, trees, grass, flooded vegetation, crops, shrub and scrub, built, bare, snow and ice.

<Callout type="mistake" title="mosaic() keeps the latest label">
`dw.mosaic()` keeps, for each pixel, the label of whichever image is last in the collection (the most recent only if you sort by date first), so it shows one date, which may fall in the monsoon or another unrepresentative time. For an annual map, the most frequent label is usually better: `dw.select('label').mode()`.
</Callout>

## Common mistakes

- **Uploading a shapefile without the .prj.** Earth Engine then assumes WGS84, so data in a projected system (such as a UTM zone) lands in the wrong place. Include .shp, .shx, .dbf and .prj (or a .zip).
- **CSV with latitude and longitude swapped,** or in a projected CRS without setting it in Advanced options.
- **Forgetting to click Run** in the Tasks tab: scripts only create tasks.
- **"Too many pixels in the region"**: raise `maxPixels`, use a coarser `scale`, or a smaller region.
- **Exporting a huge high-resolution area to Drive.** Start with one Dzongkhag, or export to an asset.

<Callout type="bhutan">
Bhutan context: for national land-cover mapping, keep the official national and Dzongkhag boundaries, training points and reference samples as shared assets in one project, and export every map and composite to that project as well. That keeps a clear record of what was used.
</Callout>
