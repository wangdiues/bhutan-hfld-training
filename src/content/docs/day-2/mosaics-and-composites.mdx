## Sentinel-2 in brief

Sentinel-2 is part of the European Commission's Copernicus programme. The first satellite, Sentinel-2A, was launched on 23 June 2015. Each satellite carries the **MultiSpectral Instrument (MSI)**: a wide-swath, high-resolution imager (10 to 60 m) designed for monitoring vegetation, soil and water, inland waterways and coasts.

| Characteristic | Value |
|---|---|
| Orbit | sun-synchronous, near-polar, 786 km altitude, 98.62° inclination |
| Orbit period | 100.6 minutes |
| Repeat cycle | 10 days per satellite; 5 days with two |
| Swath width | 290 km |
| Local solar time at the descending node | 10:30 a.m. |
| Launch mass | 1,140 kg |
| Design life | 7 years (nominal), up to 12 years |

Two products are in Earth Engine: **Level-1C** (top-of-atmosphere reflectance) and **Level-2A** (surface reflectance). Google's **Cloud Score+** cloud mask can be applied to either.

## Mosaic or composite?

Both turn many images into one, but in different ways:

- A **mosaic** places images side by side or on top of each other. Where they overlap, one image wins: in Earth Engine, `collection.mosaic()` keeps the last image in the collection on top, so sort the collection by date first if you want the latest image on top. A mosaic keeps real pixel values from single dates, but it also keeps any cloud in the top image.
- A <Term id="composite" /> builds each pixel from **all** the images that cover it, using a rule: the median, a percentile, or the "best" pixel by some score (`qualityMosaic`). A composite mixes dates, but it can remove clouds and shadows.

Run the script below to see all three side by side over Thimphu for the 2025 dry season. Switch the layers on and off in the Layers menu.

<Theory title="Why the median">
Clouds are bright and shadows are dark, so in a stack of images they sit at the extremes of each pixel's values. The median, the middle value, ignores them as long as the pixel is clear in more than half the images. It also keeps a value that really occurred, roughly, rather than averaging cloud into it, as the mean would. Masking clouds first (next lesson) means fewer images need to be clear.
</Theory>

## Pre-processing: making a composite analysis-ready

Before classification, three kinds of correction make pixel values comparable across a country and between years:

| Correction | What it removes | How |
|---|---|---|
| **Atmospheric** | the effect of gases, dust and water vapour, to retrieve surface reflectance | use Level-2A surface reflectance (Sen2Cor), as `COPERNICUS/S2_SR_HARMONIZED` does |
| **Radiometric** | sensor errors and brightness differences, so values reflect surface energy; includes **BRDF** correction | calibration in the product; BRDF normalisation in the composite |
| **Topographic** | brightness differences caused by slope and aspect: sunlit slopes look bright, shaded slopes dark | an illumination model from a digital elevation model |

**BRDF** (bidirectional reflectance distribution function) describes how a surface reflects light differently depending on the angles of the sun and the sensor. Sentinel-2 views across a 290 km swath, so the same forest looks brighter or darker at the edge of a scene than at its centre. BRDF correction normalises every pixel to a standard sun and view angle.

**Topographic (illumination) correction** matters a lot in Bhutan. The same forest on a sunlit south-facing slope and a shaded north-facing slope can look like two different classes. The correction computes how directly each pixel faces the sun, from the slope and aspect of a DEM and the sun position, and adjusts the reflectance. The course's module uses the illumination condition approach credited to Patrick Burns and Matt Macander.

<Callout type="bhutan">
Bhutan context: Bhutan rises from the southern foothills, at a few hundred metres, to Himalayan peaks above 7,000 m (Gangkhar Puensum is about 7,570 m), and in winter the low sun leaves steep north-facing slopes in shadow. Without terrain correction, shaded forest is easily mapped as a different class. Persistent cloud also means some places are clear in only a few images per season: always check how many clear observations each pixel had.
</Callout>

## The workflow as modules

The course builds a cloud-free composite in five steps, each in its own script (a **module**), called from one main script:

<Image src={modules} alt="Flow diagram of the image pre-processing modules: import Sentinel-2, shadow masking, cloud masking, BRDF correction, topographic correction, cloud-free composite, all called from a main script." />

1. **Import Sentinel-2** (`importS2_module`): set the input and output band names, filter by geometry, by date and by maximum cloud cover, and scale the values.
2. **Shadow masking** (`shadowMask_module`): remove cloud shadows.
3. **Cloud masking** (`cloud_module`): set thresholds and remove clouds, using a cloud score built on the idea of the Landsat cloud score, and the Sentinel-2 QA band.
4. **BRDF correction** (`brdf_module`).
5. **Topographic correction** (`topographic_module`): compute the illumination condition from a DEM and apply an illumination-correction function.

Then the **main** script calls them in order and exports the composite.

## Key functions

| Function | What it does |
|---|---|
| `collection.mosaic()` | Stacks images; the last one in the collection is on top |
| `collection.median()` | Median of each pixel over all images |
| `collection.qualityMosaic(band)` | Takes each pixel from the image where `band` is highest |
| `require('users/…:script')` | Loads a module (another script's `exports`) |

## Common mistakes

- **Calling a mosaic a composite.** A plain mosaic keeps the clouds of its top image.
- **Using the mean.** The mean mixes cloud and shadow into every pixel; the median ignores them.
- **Skipping terrain correction in the mountains.** Shaded slopes then look like a different land cover.
- **A wrong `require()` path.** "Cannot find required repo" usually means the account, repository or folder name is wrong, or the repository isn't shared with you.
